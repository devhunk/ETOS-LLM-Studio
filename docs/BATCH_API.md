# 厂商 Batch API

首版接入 OpenAI 的异步 Batch API：一次提交多条独立的文本请求，由厂商在 24 小时窗口内处理，之后查询和下载结果。支持 `/v1/chat/completions`，不支持 Responses、Anthropic、Gemini、多模态或需要客户端继续执行的工具调用。第三方 OpenAI 兼容服务必须实际提供 Files 与 Batch API；仅兼容聊天接口还不够。

## 使用

1. 在 iPhone 的「设置 → 拓展能力 → 批量任务」打开任务列表，点「+」。
2. 选择提供商与模型，可填写公共系统提示词。输入独立问题，每个问题之间留一个空行；也可导入 UTF-8 文本文件（最多 5 MB）。当前聊天的历史和附件不会自动加入请求。
3. 核对预览后提交。每项请求包含公共系统提示词和该问题，彼此独立。实际请求参数使用模型已有配置，强制关闭流式响应，`n` 仅支持 1。提交上限为 50,000 条请求、200 MB JSONL 文件。
4. 返回任务列表或打开任务详情刷新状态。离开应用不会中断厂商的任务，应用不会在后台持续轮询。
5. 完成后查看回答、错误与用量，导出 JSONL。过期或取消的任务也会保留已返回的结果；「仅重试失败项」会创建一个新的付费任务，原任务保持不变。

watchOS 提供查看和刷新入口。在 iPhone 创建任务后，通过现有「配置数据库同步」把记录和提供商配置同步到手表，即可查看状态与结果。创建、取消、重试、恢复关联和导出在 iPhone 上完成。

## 恢复与账号

- 提交前保存请求快照，收到文件与任务编号后分别保存进度。结果根据 `custom_id` 匹配，顺序不影响对应关系；未知或重复编号会中止导入并显示错误。
- 厂商完成状态与本地结果导入状态分开记录。下载失败后可以再次刷新，已完成请求不会自动重新提交。
- 创建任务时若连接断开，厂商可能已经接受请求。应用会显示「请确认远端提交结果」，不会自动重提。请先在厂商控制台确认，在 iPhone 的任务详情填入远端任务编号；应用会验证对应输入文件和端点。
- 任务使用提交时的第一个有效 API Key，并绑定提供商地址、Key 和请求头配置。后续上传、查询、取消与下载保持同一账号和项目，忽略聊天的多密钥轮换策略。更改原 Key、地址或请求头后，需要恢复原配置才能查询旧任务。
- 任务记录保存在现有配置数据库中，随其备份、加密与同步策略处理。记录和导出不额外保存 API Key 或认证请求头，但包含问题和回答。

## 开发验证

Linux 或 macOS 安装 Swift 6.2 后运行：

```sh
bash scripts/test-batch-core.sh
```

脚本用实际生产代码和同一套测试创建临时 SwiftPM 包，验证 JSONL、上传与认证、生命周期、重启恢复、部分失败、重复导入和失败项重试，不需要厂商密钥。

GitHub Actions 的「Batch 核心测试」运行上述检查；「PR 编译检查」在 macOS 上构建 iOS/watchOS，并运行 `BatchServiceTests` 与 `BatchAppIntegrationTests`，后者覆盖模型请求构建、项目凭据绑定和真实配置数据库持久化。Apple 平台完整编译和集成测试需要 Xcode，不能用 Linux 的语法检查替代。两个工作流也可通过 `workflow_dispatch` 手动运行。
